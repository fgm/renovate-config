One preset repo, two roles

Everything about dependency updates across the fgm/OSInet repos flows from a single public repo, github.com/fgm/renovate-config. It plays two roles at once: it holds the policy every repo pulls at run time, and it holds the runner code deployed to one host. Nothing runs automatically yet — this is the map of what's wired up.

02 Anatomy of one run

What happens end to end when ./renovate-run.sh fires on cof.

  1. Cron (or you) triggers renovate-run.sh on cof. It sources renovate.env — tokens, the version pin, and the cache paths — never logging secrets.
  2. GitHub pass: Renovate visits each of the 20 repos. For each, it reads renovate.json, resolves github>fgm/renovate-config → default.json, checks dependencies, and opens update PRs. A repo with no config gets an onboarding PR that adopts the preset.
  3. GitLab pass: same for the 2 GitLab repos. A GITHUB_COM_TOKEN is set so this non-GitHub pass can still fetch the github> preset and GitHub-hosted release notes.
  4. Output: PRs land on each repo; per-run logs land in log/. The schedule:monthly policy gates when PRs may open, independently of when the cron fires.

Last dry run (RENOVATE_DRY_RUN=full): 22 / 22 repos clean, would open 22 onboarding PRs, no OOM. The first live run therefore opens ~22 onboarding PRs.

03 Why the odd bits are the way they are

Each of these exists to solve a specific constraint on the cof host — none is arbitrary.

Setting Reason
renovate@42 pinned cof runs Node 22 (shared with the Gogs 0.15 vite frontend — must not upgrade). Renovate 43+ needs Node 24. Drop the pin once the host is on Node 24.
2 GB swapfile npm-heavy repos spike ~1 GB RSS and OOM-killed the run. Swap lives on /var/www (xfs → made with dd, not fallocate).
caches on /var/www / (20 GB) is near-full; /var/www (30 GB) is the data volume. RENOVATE_BASE_DIR + npm_config_cache keep clones and npx cache off /.
token: repo + workflow The preset pins GitHub Action digests, so Renovate edits .github/workflows/*.yml; GitHub rejects those pushes without the workflow scope.
no automerge / monthly The binding cost is your PR-review time, not compute — so batch updates monthly and keep a human in the loop.
Gogs out of scope Renovate has no Gogs platform; the 0.15-dev backend lacks /api/v1/version and /api/v1/repos/*/pulls. The Forgejo migration (WOF-47) unblocks a 3rd, Gitea-platform pass.
